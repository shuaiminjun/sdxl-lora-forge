# 实测有效 / 实测无效的做法

这份文件记的是**真的跑完之后留下来的结论**，不是理论。硬件是一张 20 GB 的 AMD 卡（ROCm），
底座是 SDXL 系（SDXL base / AnimagineXL / Illustrious），每个角色 60~120 张图。
凡是写"实测"的数字都是这台机器上的实测值，换卡会变。

## 一、caption 决定 80% 的成败

| 做法 | 结果 |
|---|---|
| 触发词放句尾 | ❌ 外形锁不住，模型把触发词当成一个普通形容词 |
| 触发词放开头、后面**紧跟类别名词**（`mychar, 1girl, ...`） | ✅ 稳定 |
| 只写触发词、不写类别名词 | ❌ 干脆画成触发词的字面意思（"鲸鱼"→画真鲸鱼） |
| 外形锚点里**漏写眼睛颜色** | ❌ 眼睛颜色随机（实测漂成紫色） |
| 把眼睛颜色写进锚点 | ✅ 稳住 |

结论：`触发词 + 类别名词 + 全部外形（含发色、瞳色、服饰、特殊饰物）`，顺序不要乱动。

## 二、数据量

| 图片数 | 步数 | 结果 |
|---|---|---|
| 20 | 900 | ❌ 只学到"有个角色"，换个场景就变脸 |
| 60 | 1200 | ⚠️ 能用，但细节薄（发丝、织纹糊） |
| **120** | **1600** | ✅ 细节明显更足，同一角色多个场景下稳定 |

60 张要训到"能用"大概 1200 步；120 张训 1600 步性价比最好（实测 30 分钟一张卡）。

## 三、训练数据不能带二次加工

造数据集时**不要开超分/精修**（ESRGAN + 二次采样那种）。原因有两个：

1. 慢一倍以上；
2. 精修会轻微改动五官，等于让 LoRA 去学一张"被算法重新想象过的脸"，反而更容易漂。

要精修就放在**出图端**，不要放进训练数据。

## 四、非方图（竖图）训练

`--res 1024 --height 1536` 这类非方图**能训**，但代价明确：

| 尺寸 | 速度 | 备注 |
|---|---|---|
| 1024×1024 | 1.07 s/step | 方图基准 |
| 1024×1536 | 1.07~1.24 s/step | 显存紧一点，速度接近 |
| 768 宽的竖图 | 更快 | 细节略掉 |

竖图的好处是**出图端不用再裁**：角色立绘、半身像这类题材，方图训练 + 竖图推理会掉构图。
代价是显存：1024×1536 在 20 GB 卡上训练时要关掉别的占卡进程，否则会撞
`LLVM ERROR: Can't get available size`（ROCm 直接 abort，不是 Python 异常）。

## 五、推理端和训练端必须一致

| 不一致 | 现象 |
|---|---|
| 训练没开 clip skip，推理开了 2 | 角色直接变（Q 版→成人、蓝发→棕发） |
| LoRA 强度拉满 1.0 | 线条变硬、脸部"塑料感" |
| 底座换了（同结构 SDXL 系） | 能加载，但配色/线条会带新底座的先验 |

经验值：LoRA 强度 **0.8~0.85**，采样 30 步、cfg 5~6、`dpmpp_2m_sde + karras` 比较稳。

## 六、什么时候该放弃训练、改用别的方案

- **只想"换脸"、不想要整个角色**：训练不对路，用 PhotoMaker 这类免训练方案更快。
- **只想要某种画风**：训一条画风 LoRA（主体多样的 60 张）比给每个角色训一条划算。
- **写真级人脸**：动漫底座怎么训都不会有真人骨相，换写实底座（RealVis 之类）。

## 七、这些结论怎么用

不需要读代码。三条命令就够：

```bash
python -m forge check --dir data/my-char                       # 数据能不能用
python -m forge caption --dir data/my-char --trigger mychar --base "…外形…"
python -m forge train-local --data data/my-char --out mychar.safetensors \
    --base ./models/illustrious-xl-v1.0.safetensors --res 1024 --height 1536 --steps 1600 --rank 32 --lr 3e-5 --tag mychar
```

训练完的 `.safetensors` 直接丢进 ComfyUI 的 `models/loras/`。
